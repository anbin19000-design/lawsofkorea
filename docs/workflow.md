# 전체 법률 검수 절차

## 범위 확인

중앙에서 배정받은 법률 묶음 하나를 끝까지 처리합니다. 기존 클라이언트의 `law_read` 결과에 있는 전체 문서 목록과 저장된 검수 범위를 확인합니다. 이 저장소는 중앙 배정을 새로 만들거나 변경하지 않습니다.

카탈로그에 연결된 법률, 시행령, 시행규칙, 별표/서식을 `catalog.expected_document_ids`에 기록합니다. 실제 목록을 확인한 경우에만 `catalog.confirmed`를 `true`로 바꿉니다. 목록에 없는 문서를 임의로 추가하거나 없는 법률 하위 문서를 만들어 내지 않습니다.

## 대조와 저장

1. 미검토 부분의 한국어 원문과 번역을 대조하고 필요한 교정만 수행합니다.
2. 단위별 ID와 원문 버전을 보존합니다. 의미·숫자·기간·인용·의무/재량·누락을 확인합니다.
3. 실제 검토한 범위만 중앙 클라이언트의 `law_checkpoint`로 저장하고 성공 영수증을 확인합니다.
4. 공개할 수 있는 영수증 참조를 `review.checkpoint_receipt`에 기록합니다. 영수증 문자열은 보안 토큰이 아닙니다.
5. 해당 단위에 `status: reviewed`, 검토자, 시간, `reviewed_source_sha256`를 기록합니다. 나머지는 `pending` 또는 `blocked`로 남깁니다.
6. 같은 법률의 미검토 부분을 즉시 계속합니다. 이미 검토·저장한 부분은 반복하지 않습니다.

원문이 변경되면 해시가 달라집니다. 변경된 원문을 다시 검토하고 새 checkpoint 영수증을 확인하기 전에는 이전 `reviewed` 상태를 유지하지 않습니다.

## 전체 완료

카탈로그가 확인됐고 모든 문서의 모든 단위를 실제로 검토한 뒤에만 `law_finish`를 실행합니다. 성공 영수증을 확인하고 `review.finish_receipt`와 `review.status: complete`를 기록합니다. 그 후에만 다음 법률을 배정받습니다.

**검수 저장과 운영 DB 반영은 별개입니다.** GitHub 커밋·PR 병합·CI 성공은 DB 쓰기를 수행하지 않습니다. 이 초기 설정에는 중앙 클라이언트나 DB 접속 코드가 없습니다.

## 차단과 보류

원문 누락이나 접근 문제는 해당 단위를 `blocked`로 표시하고 `note`에 공개 가능한 이유를 적습니다. 안전·권한 거절은 승인된 사건 원장에 기록하며, 재시도하거나 경로를 바꾸어 우회하지 않습니다. 내부 원장과 민감한 자료는 이 공개 저장소에 넣지 않습니다.

## PC 검수 이력

`reviewed/zh/<job_id>.json`에는 PC에서 저장이 확인된 중국어 검수 행과 교정문이 있습니다. `source_blobs`는 `laws/ko/<job_id>.json`과 `laws/zh/<job_id>.json`의 Git blob SHA입니다. 두 파일의 버전과 행 ID를 확인한 뒤 `checked_row_ids`의 검수 범위를 이어받고 `edits`의 교정문을 적용합니다. 같은 버전의 GitHub 전체 검수본이 있으면 `review/zh/<job_id>.json`의 최종 결과를 사용합니다.

`PARTIAL`은 일부 행의 저장을, `PASS1_SAVED`는 해당 버전 전체 행의 PC 1차 검수 저장을 뜻합니다. `law_finish_saved`는 PC에서 법령 단위 완료 영수증까지 확인한 경우에만 참입니다. 각 결과에 전체 행 수와 저장된 행 수가 들어 있습니다. GitHub 전체 검수를 완료한 결과와 영수증은 기존 절차에 따라 저장합니다.
